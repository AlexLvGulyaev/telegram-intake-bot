## 🎯 1. Project Summary

Telegram-бот для первичной обработки входящих заявок. Бот ведёт диалог с клиентом, собирает обязательные поля заявки в техподдержку или лида для отдела продаж, извлекает данные из свободного текста через LLM (OpenAI API) и отправляет структурированную заявку в Telegram-чат операторов.

**Ключевые параметры:**

| Параметр | Значение |
|----------|----------|
| Канал | Telegram |
| Язык | Python 3.12, aiogram 3.x |
| LLM | OpenAI API с JSON Schema ответа |
| Хранилище сессий | In-memory (MVP) |
| Контейнеризация | Docker |

## 💰 4. Commercial Assessment

**Потенциал:**

- Быстрый MVP для техподдержки и сбора лидов в Telegram.
- Возможность адаптации под разные сценарии сбора данных: заявки, лиды, обратная связь, запись на консультацию.
- Готовый публичный репозиторий для демонстрации заказчикам.

**Риски:**

| Риск | Вероятность | Влияние | Митигация |

| Зависимость от OpenAI API и Telegram | Средняя | Высокое | Fallback-логика, мониторинг доступности |
| PostgreSQL-режим не проходил production-нагрузку | Средняя | Среднее | ✅ Пройден E2E с `SESSION_STORAGE_TYPE=postgres`; сохранение и восстановление сессий после перезапуска контейнера подтверждено |
| Для публикации в GitHub требуется полный Deployment Validation | Средняя | Высокое | Пройти Validation на VPS и актуализировать `DEPLOYMENT_GUIDE.md` |

## ✅ 6. Decision

**Принято:** продолжить как публичный портфолио-проект.

**Утверждённые решения:**

- MVP реализован на Python 3.12 + aiogram 3.x + OpenAI API.
- Два сценария сбора данных: техподдержка и лид для продаж.
- Промпты версионированы и вынесены из кода в `prompts/`.
- Guard replies в `services/workflow.py` обеспечивают детерминированный порядок сбора полей.
- Сессии могут храниться в памяти (MVP) или в PostgreSQL (`SESSION_STORAGE_TYPE=postgres`); production-контейнер валидирован на PostgreSQL.
- Публичный репозиторий развёрнут в `AlexLvGulyaev/telegram-intake-bot`.
